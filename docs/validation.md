# DevFlow 0.1.0 の検証範囲

## 再実行方法

互換 Python 3.11 以降を使い、配布ルートで実行します。Python の第三者パッケージ、モデルのログイン、API キーは不要です。

```text
python tools/sync_shared.py --check
python tools/test_all.py --quiet
python tools/package.py --validate-only
```

各テスト群は別々の Python プロセスで実行し、モジュール名の衝突を避けます。`tests_planflow`、`tests_buildflow`、`tests_unified`、`tests` がそれぞれ計画、実装、統合ルーター、共通コード・統合・配布を扱います。テスト件数は追加に伴って変わるため、実行出力を正としてください。

本作成環境は Linux / Python 3.12.14 です。実際の uv 0.13.4 で、Python の版固定なし・offline・自動ダウンロード禁止の統合 runner 起動を確認しています。各 OS や他の Python 版の動作確認とは区別してください。

テストで作成するプロジェクトは一時ディレクトリです。実サービスにレビューを送信したり、利用者のプロジェクトにテスト用コードを混ぜたりしません。

## 自動テストの対象

- 人間の質問・回答の記録と、要約・決定事項を原文と分けて扱うこと。
- Plan と Implement の独立性、明示した Markdown のみを入力にすること。
- `.devflow/runs/{plan,implement}/` とフロー別セッション、統合設定。
- `/devflow:*` コマンド、Python の厳密な版固定を含まない runner/guard 契約。
- 設定された面接スキルの限定的なローカル診断、モデル呼び出し禁止・不足・曖昧さ・未検証の区別、Implement からの独立性。
- Codex / OpenCode を模擬するローカル CLI の別プロセス起動、引数、JSON/JSONL 結果の照合。
- 状態遷移、レビューの交互順序、合計6回の上限、送信後エラーの枠消費、再開後の保持。
- 双方による同一内容への承認、最終修正が未レビューなら成功と表示しないこと。
- 正式プランの保存条件、同一バイト列、パス逸脱・symlink・既存ファイルの上書き拒否。
- 必須チェック、人間検証、ソースを変えるチェックの拒否、検証前後のスナップショット照合。
- 開始前の利用者変更の保全、最終レポートの改ざん検出、失敗時・中断時の復旧。
- 一つの marketplace entry、単一のインストール対象、共有コードの生成先の一致。
- ZIP を展開し、プラグインだけを別の場所へ置いてもエントリーポイントを起動できること。
- Python 3.11 構文としての静的解析、ZIP 再現性、全ファイル SHA-256、実行履歴・秘密ファイルの除外。

## この作成環境では確認しないもの

- Claude Code 本体での plugin インストール、外部 `grilling` を含む実際の skill 展開、hooks の実行。
- 認証済み Codex / OpenCode と実サービスの接続、課金・レート制限、モデルの利用権限。
- `gpt-6.1-sol`、`opencode-go/deepseek-v4.1-flash` および effort 設定のアカウントごとの提供状況。
- サービス内部で実際に選択されたバックエンドモデルの独立した証明。
- Windows ネイティブ / macOS / WSL、ネットワークドライブや exFAT でのライブ動作。
- 同梱の Python / Next.js / Unity 設定例を利用者の実プロジェクトで実行した結果。

コードとテストは OS 依存を抑えていますが、「クロスプラットフォームを意図した設計」と「すべての OS で実動作確認済み」は異なります。GitHub Actions には Linux / macOS / Windows × Python 3.11 / 3.12 / 3.13 の設定を同梱します。実行成功は各リポジトリの Actions で別途確認してください。

## 初回利用時の受け入れ確認

1. Claude Code **2.1.295 以降**、`uv`、インストール済み Python 3.11 以降、外部 CLI、通常の認証を用意します。Plan ではモデルから呼び出せる外部 `grilling` も用意します。
2. `claude plugin validate ./plugins/devflow` で対象端末の Claude Code が構成を受理することを確認します。
3. `/devflow:doctor` で設定と CLI を診断します。offline の診断だけでモデルの利用権限を確認したことにはなりません。
4. 秘密を含まない小さなテストプロジェクトで Plan → 正式保存 → 明示的な Implement を実行します。
5. 人間判断待ち、失敗、再開、上限到達時の報告が期待どおりか確認します。
6. 実プロジェクトの検証コマンド、対象範囲、外部送信の可否を人間が承認してから利用します。

これらのテストはフローの制約と失敗時の振る舞いを確認するものであり、AI が作るプラン・コードの正しさや、無人本番運用の安全性を保証しません。
