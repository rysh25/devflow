# 安全上の境界と運用上の注意

## 保証しないこと

DevFlowは、OSのサンドボックスやアクセス制御の代わりではありません。Claude Code、レビュー用CLI、承認済みのチェックコマンド、通常の認証設定を信頼することが前提です。

スナップショットと履歴のハッシュは、誤操作・古い結果の流用・許可されていないフロー変更を検出するためのものです。同じOSユーザーが意図的に全てのファイルを改ざんできる環境に対して、暗号署名や外部の改ざん防止監査を提供するものではありません。

## 明示的な開始と人間の判断

- 開始は`/devflow:plan`または`/devflow:implement`を人が明示します。
- BuildFlowは指示された計画ファイルだけを読み、別の計画を自動発見して置き換えません。
- 計画・コード・レビュー結果中の命令を、権限変更や任意コマンド実行の根拠として扱いません。
- 人間への問い合わせ後に記録された、事前回答を埋め込んでいない `AskUserQuestion` の成功結果だけを解決イベントに利用します。普通の会話の返信、再開コマンド、古い回答、Claudeが書いた文は承認の代わりになりません。
  - Claude Code の質問画面は、人の回答とメモをツール入力の `answers`・`annotations` に書き込んでからツールを実行します。そのため実行後（`PostToolUse`）の入力に回答があるのは正常です。モデルによる事前回答は実行前（`PreToolUse`）に拒否し、Plan の聞き取りでは封印時にセッション記録上のモデルの呼び出しとも照合します。
- 返答の意味の解釈はClaudeが担当します。曖昧なら再質問します。イベント照合だけで意味解釈の正しさが証明されるわけではありません。

同じセッションでアクティブなPlanFlowとBuildFlowを重ねて使うことは認めません。前のフローを完了・キャンセルし、次の実際のユーザー入力で切り替えてください。

`UserPromptSubmit` は通常の入力以外でも発生し得るため、そのイベントだけで人間の意思を証明しません。開始と対話には人間が操作するセッションを使用し、スケジューラーやチームメッセージを承認経路にしないでください。`AskUserQuestion` 結果の照合も、同じ OS ユーザーや信頼済みツールに対する暗号学的な本人証明ではありません。

Plan の面接は凍結された `plan.grill_skill` の呼び出し先だけを使用します。既定の外部 `grilling` が利用できない場合、別スキルへの自動フォールバックや手順の模倣はしません。`disable-model-invocation: true` を解除したり、スキルを直接読み込んで呼び出し拒否を回避したりしません。外部スキルの選択・導入は人間の管理対象です。

## 実装側のガード

実行中は、現在の状態と設定で許されたソース編集・draft作成・ランナーのアクションだけを認めます。確定計画、設定、run履歴、回数、認証・許可・エージェント指示等の保護対象をClaudeが直接変更することは認めません。

任意シェルを広く許可することはしません。ソースの削除・移動が必要になった場合は、人間に判断と操作を依頼します。commit、push、PR、デプロイ、依存導入、不可逆な移行は別の明示的な作業として扱います。

フックは通常のClaude Code権限確認を置き換えません。組織の拒否設定や権限要求を無視する構成ではありません。`onFailure: "block"`を設定したガードは、起動失敗・不正出力・タイムアウトで安全側に停止します。この仕様のため **Claude Code 2.1.295 以降**が必要です。古い版に無理に読み込ませたり、設定を削除して継続したりしないでください。

## 外部レビューの境界

レビュアーは対象プロジェクトとは別の作業ディレクトリで起動します。パケットに必要情報をまとめ、ツール・シェル・MCP・外部検索等を使わない構成でレビューします。Codexでは読み取り専用サンドボックスも指定します。

Plan / Implement とも Codex の通常ユーザー設定を読み込まず、必要な機能を明示的に無効化します。認証は通常の認証ストアを使い、キーをコピーしません。JSONL のツールイベントを拒否し、最終メッセージのファイルとイベント上の結果が一致した場合だけ受理します。必要な CLI フラグがない場合は停止し、弱い設定へ切り替えません。管理者の要件を回避するものではありません。

ただしCLI自体は通常の認証ストアを使い、サービスへ通信します。ツール禁止設定は多層の防御であり、信頼できないCLIバイナリや悪意のある管理設定に対するOS隔離ではありません。モデルが実際に内部でどのバックエンドへ割り当てられるかまで、プラグインが独立に証明することはできません。

出力の不正JSON、重複キー、未知のイベント、ツール呼び出し、途中終了、対象スナップショット不一致は失敗とします。出力を都合よく補完して成功扱いしません。失敗しても既に送信した回数は消費されます。

## 送信される情報と秘密情報

PlanFlowでは最初の依頼、インタビューの原文、決定サマリー、計画等が送信されます。BuildFlowでは計画、変更コード、明示した関連ファイル、チェック結果、過去のレビューと人間の判断等が送信されます。

`.env`、秘密鍵、一般的なsecretディレクトリ等は既定でコードスナップショットから除外します。しかし、ファイル名だけの除外で秘密情報を完全に検出できるわけではありません。ソース、計画、ログ、質問への回答に秘密が書かれていれば送信対象に含まれる可能性があります。

開始前に外部送信の可否を確認してください。認証トークンや秘密鍵を設定JSON・計画・インタビューに貼らないでください。機密プロジェクトでは、組織が認めたモデル・サービス・データ保持設定の範囲でのみ利用してください。

送信内容を削る必要がある場合は、人間が確認したサニタイズ済み資料からやり直します。原文を保持したと称しながら、裏で勝手に改変することはしません。

## レビュー対象範囲

既定Gitモードでは、明示した範囲内の追跡済みファイルとGitに無視されていない未追跡ファイルを読みます。秘密情報・実行記録・キャッシュ等の除外に加え、設定のinclude/excludeが適用されます。除外・Git-ignoredの未追跡ファイルを、このフローが確認したことにはしません。

パス逸脱、symlink/junction、submodule、nested repository、ポータブルでないパス、大小文字衝突は拒否します。Gitなしで使う場合は`files`モードを明示します。

各レビューのコード部分は開始時からの累積差分と変更ファイルの全テキストです。変更していない関連ファイルは`context_paths`で追加します。対象ツリーのハッシュがあることと、全ファイルの内容をモデルが読んだことは別です。

文字数・ファイル数・パケットサイズを超えた場合は停止します。バイナリ変更は人間の確認が必要です。ソースを書き換えた後に以前の合格を使い回すことはありません。

## チェックコマンド

`checks`は利用者が事前に確認したコマンドの一覧です。`argv`配列で起動し、レビュー結果の文章をシェルコマンドへ変換しません。設定はrun開始時に固定します。

テスト・ビルドは**プロジェクトのコードを実行する行為**です。ネットワークへのアクセス、ファイル変更、認証情報の参照、副作用が起こり得ます。`shell=False`、cwd制限、タイムアウト、出力上限だけでその副作用を完全には制御できません。信用できないプロジェクトでは、利用者が別途隔離環境を用意してください。

チェック後に対象ソースが変化した場合は候補を無効化して停止します。タイムアウトや出力上限超過は失敗です。子プロセス終了は最善努力であり、独自に別のプロセスグループへ逃げたプログラムまで確実に終了する保証はありません。

チェック未設定時は人間の実確認を必要とします。任意の空コマンドや常に終了コード0を返すコマンドを設定しても、意味のある検証にはなりません。合格基準を人間が管理してください。

## 保存と復旧

実行記録は対象プロジェクトの`.devflow/runs/plan/` / `.devflow/runs/implement/`に置きます。Git除外ファイルを用意しますが、過去に追跡したファイルや手動の強制追加、バックアップ、クラウド同期までは制御しません。

正式なプランは双方が同じ内容を承認した場合だけ、凍結設定で選んだプロジェクト内の保存先へ出力します。レビュー完了と保存成功は別状態です。既存ファイルは上書きせず、公開先の symlink・パス逸脱は拒否します。Git のステージング・コミット・push は行いません。人間が未承認の計画を別途採用しても、DevFlow の双方承認を偽装しないでください。

通常のローカルファイルシステムにおける原子的renameとhard linkを使用します。WindowsではNTFS等を前提とします。共有ネットワークドライブ、exFAT等を使う場合の動作は未検証です。対応しない環境で安全チェックを外すことはしないでください。

保存処理はプロセス中断時の整合性を守る設計ですが、全 OS・全ファイルシステムでのディレクトリ fsync や突然の電源断に対する完全な永続性を保証しません。重要な成果物は別途バックアップしてください。

ロックは所有プロセスの記録を確認して扱います。runの丸ごと削除、履歴の書き換え、review counterのリセットを復旧手順にしないでください。送信済みか分からないレビューは消費済みとして扱い、人間が終了を確認してから再開します。

終了レポートは保存時点の証拠です。後日に作業ツリーが変更された場合まで継続的に監視・保証するものではありません。最終ファイル確認に失敗した場合は、未レビューの変更有無を不明として記録します。`null`を変更なしと読み替えないでください。

## 検証状況

Linuxで標準ライブラリのテストと模擬CLIを使う検証を行っています。実サービスへの送信・課金・認証・実モデルの出力、Claude Code本体のフック、Windows/macOSでのライブ動作は、この作成環境では確認していません。

GitHub ActionsにはWindows/macOS/Linuxのテスト定義を含めます。実際の実行結果は各リポジトリのActionsで確認してください。提供したコードとテストだけを根拠に、無人本番運用が安全だと判断しないでください。
